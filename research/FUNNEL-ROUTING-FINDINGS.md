# 缩候选提速：族路由 + 定位器（2026-08-26 fork research）

任务：加速"~4.7 万起点 → 候选"这一步（慢洞如 795 的 NESTPROBE 强筛吃 217s）。

## 核心发现：定位器适用面比以为的宽，族路由规则干净

**族路由规则（已验证）**：撒 4×4=16 个远样本、跑 Python 裁判（~15-20s 单核）：
- 有样本被杀 → 找到双杀模体 → **flow 族** → `rescue.py` 秒级出紧候选。
- 16 样本全存活、0 模体 → **有向族** → 退回 C NESTPROBE 强筛。

实测分类：
| 关 | 样本存活 | 模体 | 定位器候选 | 含真解 |
|---|---|---|---|---|
| 770 | 0/16 | 1 | 239 (0.53%) | ✓ (86,57) |
| 799 | 0/16 | 1 | 112 (0.23%) | ✓ (133,121) |
| 795 | 16/16 | 0 | 不适用 | — (走 C funnel) |

**795 才是有向族例外，不是常态**——flow 族（770/799…）定位器都能用。

## 提速量化（799，flow 族）

| 缩候选方式 | 墙钟 | 核 | 核秒 | 输出 |
|---|---|---|---|---|
| **定位器** | 17.4s | 1 | **17** | 112 候选 |
| C NESTPROBE | 97s | 26 | **2522** | 2 幸存 |

- 缩候选这一步 **~150× 省算力**（17 vs 2522 核秒）。
- 端到端（定位+求解，JOBS=1）：**135s，有效解出 799**（vs funnel 路径 ~2558 核秒 → **总算力 ~19×**）。

## 权衡与注意

- 定位器候选（112）比 funnel 幸存（2）**松** → 下游 sweep 候选更多。但 BJ=500 让死候选秒死，净赚。
- **松候选需并行 sweep（JOBS=26）才发挥**；JOBS=1 顺序扫 112 会主导耗时（实测求解段 118s）。
- 改进：给 STARTORD 候选真实 F 值（营救裕度排序），让赢家排前面，低并行也快。

## 有向族（795）

- 定位器空跑（13.8s，0 候选）→ 必须 C funnel（217s）。
- 747 不对称定理：有向边强制无 max-flow 对偶，无 rescue 式捷径。217s 是否为该族下界、funnel 内部能否更便宜预筛——本轮未深挖。

## soundness

定位器区域 = 真候选**超集**（R3 理论；770/799 真起点均落区，PASS）。安全。

## 建议

把**族路由**做成默认 funnel 入口：秒级判族 → flow 族走定位器（跳 C funnel，缩候选 ~150× 省算力）→ 有向族走 C funnel。提速 flow 族多数关；有向族（795 类，较罕见）不变。
