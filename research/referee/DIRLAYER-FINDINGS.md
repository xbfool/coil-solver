# 裁判有向层移植 —— 强制边族(747)定位器的"最后一块"（2026-08-26）

目标：把营救区域定位器从 **flow 族**（767/703/736）扩到 **强制边族**（747），
让 `localize.py 747` 像 flow 族一样秒级定位并落区含真解 (12,19)。

## 做了什么

把求解器 v73 **有向层**（`versions/v77-deepprune.c`: `set_dir`/`dprocess`/`ord_reach`/`drun`）
移植进 Python 裁判 `referee.py` 的 `Propagator`（每起点相、非全局、非树内）：

- **走向变量** `dirv[c*4+e]`：0 未定 / 1 = 路径 c→c+e / 2 = 不走。
- **规则1** 与 estate 双向喂（禁边⇒两向皆否；必用边⇒恰一向；两向皆否⇒禁边，反哺无向层）。
- **规则2** 出/入度：非终点恰一出、非起点恰一入（终点色由奇偶定，真终点那格只降级为"至多一个"）。
- **规则3** 滑行反对称 + `ord_reach` **时序找环**（有界 DFS：`T(c,e)` 转弯⇒ t(c+e)<t(c)；沿"更早→更晚"链成环=矛盾）。
- 驱动 `dir_layer()`：有向 drun 与无向 drain 交替到不动点（判定数单调增，必终止）。
- 接线：`run()` 在两轮 flow 之后、`chains_check` 之前调 `dir_layer()`。开关 `DIRLAYER`（默认 2；0=关，1=只规则1~2，2=加滑行/找环）。

## 关键发现（负结果，恰是理论"最后一块"）

**平凡有向传播杀不动 747 的远起点。** 实测：`localize.py 747` 撒 16 个远样本，
有向层跑满（钉 (90,90) 设定 58464 个走向变量、判定数 61880→120344），**16/16 全存活、0 模体**。
远起点从空起点出发不产生矛盾。

747 的击杀机制是 **嵌套有向探针**（NESTPROBE，求解器 `dir_probe`/`try_dir_v`）——
2 层前瞻 + 累积学习（假设走向 X→传播；对前沿变量 Y 双值试；两边皆矛盾⇒X 不可能；
一边矛盾⇒把 Y 定进 X 的试验态再传播）。漏斗正是靠它把 747 筛到 24 个幸存者（针尖）。

### 为什么 Python 定位器覆盖不了强制边族（两道硬墙）

1. **嵌套探针在 localize 环里不可行**：外层 4N 个走向假设 × 内层 nest_k × 每次 drun，
   44k 盘 ≈ 10¹⁰ 次操作/起点。C 里快，Python 里每起点数小时——localize 撒样本这一步就跑不动。

2. **rescue.py 的快速区域演算是 flow 专属的**：它对每条模体边做一次 max-flow + 残量 BFS，
   本质是 **Régin 强制的对偶**（删边后模型是否仍饱和 ⟺ 该起点能否营救此边）。
   而强制边族的模体边是**滑行时序可达性**强制的，不是二部匹配/流——**没有 max-flow 对偶**。
   即便拿到 747 的有向模体，算营救区域仍要**逐起点跑有向传播**（44k 起点，Python 不可行）。

### 结论：两族是**非对称**的

- **flow 族**（767/703/736）：有快速 Python 营救对偶（每模体边一次 max-flow）⇒ **秒级定位器**。✓
- **强制边族**（747）：**无**快速 Python 对偶（约束不是流）⇒ 其"定位器"就是 **C 漏斗的嵌套探针本身**
  （已产出 24 个幸存者针尖，左上角 x∈[1,35] y∈[13,48]，真解 12,19 在其中）。

这条**非对称性**（一族有快对偶、一族没有）就是理论缺的最后一块：
不是"再补个探针就统一了"，而是**流族可秒级、有向族只能靠 C 漏斗**——机制层级不同，可 tractable 性也不同。

## 这次移植仍然买到了什么

- 一个**更强且健全**的 Python 裁判：有向层的判定与地面真值零冲突，可用于**独立验证/认证**
  （certify/selftest 现在带走向+滑行时序，比原来的 §3.4/§3.5 强）。
- flow 族定位器**未受影响**（flow 先杀，模体不变，回归全绿）。
- 若日后要真的秒级定位 747 族：出路是**把嵌套探针移到 C 速**，或**instrument 求解器 `dir_probe`
  在杀远起点时 dump 模体**——但**区域演算这道墙仍在**（有向强制没有 max-flow 对偶，区域步仍需逐起点传播）。
  换言之，747 族的正确工具本来就是 C 漏斗，不是 Python rescue 演算。
