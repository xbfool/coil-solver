# 攻关加速 research：767 型"81 分钟"到底卡在哪（诚实版）

日期 2026-08-26。research 独立于 main。原型 `versions/v78-rpbj.c`（`ADAPT=1` / `RPBJ=N`）。

## 问题
用户直觉：一关 81 分钟不对，有大剪枝没挖出来。

## 核心结论（数据驱动，纠正了协调者的两个假设）
**剪枝没缺失——父机的 BJ=20 早已把 767 赢家树塌了 25×。** 真正的瓶颈是武器的 **O(N) 每节点成本** + **swarm 起点穷举**，不是缺剪枝。

### 单核钉 767 赢家(115,197) BJ 密度扫（决定性）
| 配置 | 结果 | 每节点速率 |
|---|---|---|
| BJ=0 基线 | **28M+ 节点 / 150s 未解**（树太大穷不完） | 187k/s |
| **BJ=20（父机配置）** | **1.05M / 139.7s 出解** | 7.5k/s |
| BJ=100 | 1.08M / 85.1s | |
| BJ=500 | 1.2M / 73.5s | |
| ADAPT | 1.1M / 74.7s（官方 check 合法）| |

**读法**：帧入口强制边把树塌 25×（28M→1M），但 BJ=20 每 20 节点跑一次 O(N) 全播 → 每节点慢 25×（7.5k vs 187k/s），**节点省的和每节点变贵的几乎抵消**。所以 BJ=20 只是让 767 从"穷不完"变"能解"，不是变快。**稀疏 BJ(500)/ADAPT 才快 ~2×**（73s vs 140s）——少付 O(N)、树照塌。

### 帧入口 vs 候选位（团队为何低估强制边）
`propagate_dyn` 挂在**候选生成**位（line 2552 PDEVERY）767 型仅 3% → 判"无用"。同一传播器挂**帧入口**位（BJ line 2530，分支前查本帧全播）767 型 **38%**。挂载位置的差别，不是技术。

## 决定性归因（同稀疏度 period 500，纠正协调者"incrementalize region_parity"）
| 武器 | L750 | L748 |
|---|---|---|
| **帧入口 pd 单独** (BJ=500) | **6.5s / 173k** | **11.3s / 492k** ← 最快 |
| 帧入口 rp 单独 (RPBJ=500) | 14.0s / 186k | 50.7s / 760k |
| both (ADAPT) | 13.7s / 159k | 18.1s / 172k |

**pd 单独是两型最快的墙钟配置。** region_parity 的 O(N) Tarjan 每节点比 pd 慢 5×——ADAPT 节点更少(172k)但 rp 的成本让它比 pd 单独还慢(18.1 vs 11.3s)。
⇒ **协调者要 incrementalize 的 region_parity 是净负收益武器。真正该做的：默认用稀疏帧入口 pd（BJ=500，丢掉 rp）；要增量化就增量化 pd（不是 rp）。**

## 三个真正的墙钟杠杆
1. **增量化 propagate_dyn（最大杠杆）**：树已塌到 ~1M 节点；若每节点回到基线 187k/s，1M 节点 ≈ **6 秒**（现在 74s，因 O(N)）。把全播改成增量维护 estate 是 ~10-25× 墙钟杠杆。
2. **定位器起点优先**：赢家树单核 74s；81 分钟 swarm = 穷举 ~87 幸存起点 × 各 ~1M 节点。让 swarm 先搜定位器给的赢家起点 → 分钟级。
3. **BJ 稀疏/自适应（易得 ~2×）**：父机 BJ=20 太密、浪费 O(N)。ADAPT 自动找到甜点（≈BJ=500）。

## 统一自适应武器组 ADAPT=1（消除 747/767 分叉，达成"不分叉"验收）
帧入口 {region_parity, propagate_dyn} 各按滑窗命中率自调密度。**同一配置零 per-type 开关**两型都塌树出解：767 型 L750 159k/14.7s、L748 172k/19.3s、**767 1.1M/74.7s**；747 型 L747 260k/21.2s。propagate_dyn 两型都自动加密（主力），region_parity 仅产出处加密。速度 ≈ 调好的稀疏 BJ，价值在**免手调 + 统一**。
