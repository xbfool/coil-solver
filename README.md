# coil-solver

给 [adum/coilbench](https://github.com/adum/coilbench) 写的 Coil 解题程序。**上游仓库里没有任何答案**
（关卡文件只有棋盘，校验器 `check.c` 是纯模拟器，走一遍数还剩几格没走到），所以这里是从零写的。

## 题目

网格里选一个空格出发，每次选一个方向就**一直滑到撞墙/撞边界/撞已访问格子**才停，然后重新选方向。
要求每个空格恰好走一次。本质是空格集合上的哈密顿路径，只是拐弯时机被滑动规则限死。

评测是**一个程序打全部关卡**：评测脚本按关号依次把棋盘喂给 `./run_solver`（stdin 进、stdout 出，
每关 600 秒），失败即停，成绩 = 通过的最高关号。程序看不到关号，只看到棋盘，所以没法按关特判。
难度只有一个维度——棋盘大小：L1 是 3×3，L1207 是 1990×1990。

## 当前进展（详见 notes.md）

- **最好成绩：30 秒/关 → 第 215 关**（v17/v18/v19，官方 evaluate.py 口径，107 关全过校验器，零 FAIL）
- 官方 results.md 用的是 **600 秒/关**：各家模型 47～117，最高 kimi 2.6 的 264。还没跑 600 秒口径。
- 这一轮从 175 涨到 215，三步：
  1. **v13** 修掉 v11 的并行失效 bug（`emit()` 写了却从没被调用，父进程不 kill 其余子进程，
     实测耗时一直是「最慢的核搜穷自己那片」而不是「最快的核找到解」）：175 → 193
  2. **v16** 把每节点的全盘洪水填充换成**等价**的局部连通性检查（只需验证「被吃掉的那条直线的
     自由邻居两两连通」），剪枝强度不变、常数降 4~5 倍：193 → 213
  3. **v17** 约束传播（见下），每个起点开搜前跑一次，定死的边拿去剪滑行候选：213 → 215
  4. **v18/v19** 传播搬进搜索当浅层分支剪枝、加有向层（链定向 + 首步滑行）：单关更稳，分数持平
- **v9 的约束传播这次起爆了**。它当年空转不是因为环模型建错了，而是因为**没有起爆点**：
  度 2 规则要「这一格恰好用 2 条边」，可路径的两个端点只用 1 条，端点是谁又不知道。
  种子在奇偶上——路径两色交替，所以**起点一旦假定，终点的颜色就被完全确定**，
  一半的格子当场被证明绝不是端点，度 2 规则就能锁死了。真起点下能定死 25%~49% 的边。
- 已证实：真实关卡**解常常唯一**（L99/L139 只有 1 个有向解）；盘面是照着有解构造的
  （无度1格、墙的两色数量完全相等）；沿真解 **87% 的步只有一个候选**。
- 还没解决的大问题没变：**搜索路线的天花板 ≈ L350~450**（节点数 ≈ e^(0.0027×自由格)）。
  要打 1000 关必须让传播强到把搜索基本消灭掉——Tron 通关 1206 关走的就是这条，
  预处理后只剩 0.3% 的格子不确定用哪两条边。那需要**有向层**（「从某侧进入某格」），
  纯无向的结构层装不下 Coil 的时序约束。有向层的三条规则已经做出来了（v19，都验过 soundness），
  但撞上一条硬约束：**自由格数 n 为偶数时，「假定起点」是放松约束而不是收紧**
  （起点终点异色，起点色的格子本该挂满 2 条边），放松永远推不出矛盾——偶数关证伪率因此只有 0.4%，
  奇数关则有 58%。而 evaluate.py 只跑奇数**关号**，那些关的 n 恰好恒为偶数。详见 notes.md。

## 用法

需要 WSL（Windows 侧没有 C 编译器，且上游脚本是 POSIX sh）：

```bash
wsl -e bash -lc "cd /mnt/d/works/coil-solver && ./bench --start 1 --timeout 60"
```

`bench` 会编译版本源码 → 拷进 coilbench 当 `./solver`（`run_solver` 会优先跑它）→ 调官方
`evaluate.py`。coilbench 默认找**同级目录**，可用 `COILBENCH_DIR` 覆盖。

**关卡包不用口令**：`download_full_levels.sh` 里的口令只是用来把偶数关加密存档的，关卡本体在
公开 release 直接下载 —— `releases/download/data-v1.0/boards.zip`（47MB，1207 关）。
解开后奇数关放 `levels_public/`（`evaluate.py` 用），全部 1207 关放 `levels_all/`（单关调试用）。

两个环境坑：编译要 `-std=gnu99`（gcc 15 下 `-std=c99` 会把 POSIX 声明藏起来，`kill()` 变成
隐式声明，而隐式声明在新版是错误不是警告）；clone coilbench 要 `core.autocrlf false`，
否则 CRLF 会让 WSL 里的 `#!/usr/bin/env python3` 起不来。

## 版本

每个版本单独一个文件，`./bench <版本名>` 直接对比。当前最好的是 `v19-chainorient.c`（等于 v17/v18 的分数，但多带有向层）。

`versions/v1-dfs.c` — 滑动 DFS：

- **滑动 DFS**：状态 = 位置 + 已访问集合，每步枚举 4 个方向滑到底
- **连通性剪枝**：每个节点从当前位置洪水填充，剩余空格必须全部可达，否则剪掉
- **死端剪枝**：统计只剩 ≤1 个出口的未访问格子，超过 1 个必然无解（路径只有一个终点）
- **Warnsdorff 排序**：优先走向出口最少的落点
- **起点排序**：度数小的格子优先（度 1 的格子必然是路径端点）
- **迭代放宽**：先给每个起点浅搜（30 万节点），全失败再把上限 ×8 重来，避免卡死在坏起点上

每个版本单独一个文件放在 `versions/`（`v1-dfs.c`、`v2-*.c` …），跑 `./bench <版本名>` 直接对比，
不用翻 git 历史。成绩表和迭代观察见 `notes.md`。
